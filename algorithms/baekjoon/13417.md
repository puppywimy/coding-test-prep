### 문제 및 풀이 날짜

- https://www.acmicpc.net/problem/13417
- 2025-11-27

### 문제 분석 요약

그리디

### 제한사항

- 1 ≤ 카드의 개수 N ≤ 1,000

### 알고리즘 설계

그리디하게 알파벳 순서가 빠른 건 앞으로 느린 건 뒤로 보내면서 풀면 될 것 같은 느낌이 들었는데, 항상 정답이 나오는지 확신이 없었다.<br />
그래서 예시를 몇 개 그려보고 다음과 같은 사실을 알게 되었다.

```
문자열을 처음부터 끝까지 만들어갈 때, 새로 들어오는 문자를 기존 문자열의 "앞에 둘지, 뒤에 둘지 두 가지 선택지밖에 없다."
이때 사전 순으로 가장 앞서는 문자열을 만들고 싶다면, 새 문자와 현재 문자열의 첫 문자만 비교하면 된다.

- 새 문자가 첫 문자보다 작거나 같다면 앞에 둔다.
- 새 문자가 더 크다면 뒤에 둔다.

왜 이게 항상 최선인가?
"앞부분은 문자열의 사전 순서를 결정하는 가장 중요한 요소"이기 때문에, 새 문자가 더 작다면 가능한 한 앞으로 보내는 것이 전체 문자열을 사전 순으로 더 빠르게 만드는 데 항상 유리하다.
그리고 이 선택은 "이후 과정에도 동일하게 적용"되므로, 매 순간 이런 방식으로 결정하면 전체 문자열도 최적이 된다.
```

이렇게 해서 매번 새 문자를 앞 또는 뒤에 놓는 간단한 그리디 전략이 항상 정답을 보장한다.

추가로, js에서의 unshift() 시간 복잡도를 모르고 있었지만 전체 시간 복잡도가 O(N^2)이어도 최대 1,000,000번 수행되는 것이므로 사용해도 괜찮을 것이라 생각했다.

### 코드

```js
const fs = require("fs");
const rawInput = fs.readFileSync(0, "utf-8").trim();

function solution() {
  const [rawT, ...rows] = rawInput.split("\n");
  const T = Number(rawT);
  for (let i = 0; i < T; i++) {
    const N = Number(rows[2 * i]);
    const cards = rows[2 * i + 1].split(" ");

    let cursor = 1;
    let output = [cards[0]];
    while (cursor < N) {
      const currentCard = cards[cursor++];
      if (currentCard > output[0]) {
        output.push(currentCard);
      } else {
        output.unshift(currentCard);
      }
    }

    console.log(output.join(""));
  }
}

solution();
```

### 시간 복잡도

**O(N^2)**<br />
cards를 앞에서부터 순회하며 문자열을 완성(`push()` 또는 `unshift()`)하기 때문이다.
