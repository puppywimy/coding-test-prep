### 문제 분석 요약

스택 활용 문제

### 제한사항

- 1 ≤ N ≤ 1,000,000
- 1 ≤ A_i ≤ 1,000,000

### 알고리즘 설계

투포인터인가? 이진탐색인가? 어떤 방법을 떠올려도 O(N^2) 아래로 시간 복잡도를 낮출 수 없어서 GPT에게 도움을 받았다.<br />
스택을 활용하는 것은 생각지도 못 했다..

1. 각 숫자들을 순회하며 다음을 반복한다.
   1. 스택의 top에 있는 숫자와 현재 숫자를 비교한다. 현재 숫자가 더 크다면 현재 숫자는 top의 오큰수다.
   2. 오큰수를 찾았다면 스택을 pop한다.
   3. 1~2를 가능할 때까지 반복하고 현재 숫자를 스택에 push한다.
2. 스택에 남아있는 숫자들은 오큰수를 찾지 못 한 숫자이므로 -1 처리를 한다.

처음에 풀이 방법을 확인해도 이해하지 못 했는데 그 이유는 시간 복잡도 때문이었다.<br />
N번 순회하면서 스택의 원소들(최대 N개)을 비교하므로 O(N^2)이라고 생각했다.<br />
하지만 스택에는 각 원소가 한 번씩만 push·pop 되며, 항상 오름차순(top-bottom 방향) 정렬되어 있기 때문에 top만 비교하면 된다. (pop하고 다시 top 비교, 이런 식)<br />
즉, 총 비교 횟수도 N번이 된다.<br />
따라서 O(N)의 시간 복잡도로 풀 수 있는 방법이다.

### 코드

```js
const fs = require("fs");
const rawInput = fs.readFileSync(0, "utf-8").trim();

function solution() {
  class Stack {
    constructor() {
      this.array = [];
      this.top = -1;
    }

    push(x) {
      this.array[++this.top] = x;
    }

    pop() {
      return this.array[this.top--];
    }

    getTop() {
      if (this.top === -1) return null;
      return this.array[this.top];
    }
  }

  const [[N], numbers] = rawInput
    .split("\n")
    .map((row) => row.split(" ").map(Number));
  const oknsus = [];
  const stack = new Stack();
  stack.push([0, numbers[0]]);
  for (let i = 1; i < N; i++) {
    while (stack.getTop() && numbers[i] > stack.getTop()[1]) {
      oknsus[stack.pop()[0]] = numbers[i];
    }
    stack.push([i, numbers[i]]);
  }
  while (stack.getTop()) {
    oknsus[stack.pop()[0]] = -1;
  }
  console.log(oknsus.join(" "));
}

solution();
```

### 시간 복잡도

**O(N)**<br />
순회 횟수가 N이고, 총비교 횟수도 N이어서 최대 2N만큼 연산이 수행된다.
