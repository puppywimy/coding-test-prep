### 문제 분석 요약

문자열 정렬

### 제한 사항

- numbers의 길이는 1 이상 100,000 이하입니다.
- numbers의 원소는 0 이상 1,000 이하입니다.
- 정답이 너무 클 수 있으니 문자열로 바꾸어 return 합니다.

### 알고리즘 설계

각 숫자를 문자열로 변환해서 사전 순 정렬하면 되겠다 해서 풀었는데 "3"과 "30" 비교 케이스에서 틀렸다.

풀이 시간을 초과하여 Claude한테 내가 생각한 비교 방식이 맞는지 확인해봤는데 아예 두 문자열을 합쳐서 비교하는 천재적인 방법을 알려줬다..

추가로 `"00"`과 같은 엣지 케이스를 조심하도록 한다.

### 코드

```kt
class Solution {
    fun solution(numbers: IntArray): String {
        val string = numbers
            .map { "" + it }
            .sortedWith({ a, b -> (b + a).compareTo(a + b) })
            .joinToString("")
        return if (string[0] == '0') "0" else string
    }
}
```

### 시간 복잡도

$$O(n\log{n})$$

sortedWith은 JVM에서 TimSort(O(nlogn))로 구현되어 있다고 한다.

### 느낀점 or 기억할 정보

- 아직 kotlin이 익숙하지 않은 것 같다.. 문제를 많이 풀면서 메서드를 익혀놔야겠다.
- 비교 함수에서 문자열을 합치기 때문에 복잡도를 n^2logn으로 생각했는데 비교 함수 복잡도는 n이 아닌 문자열 길이로 결정되는 거라 아니었다.
- 커스텀 비교 함수로 정렬할 때는 `sortedWith({ a, b -> ... })`을 사용한다.
