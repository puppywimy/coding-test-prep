### 문제 분석 요약

DP 문제

### 제한 사항

- n은 100,000 이하의 자연수입니다.
- 화폐 단위는 100종류 이하입니다.
- 모든 화폐는 무한하게 있다고 가정합니다.
- 정답이 커질 수 있으니, 1,000,000,007로 나눈 나머지를 return 해주세요.

### 알고리즘 설계

경우의 수를 구하는 거라 경우를 일일이 구하는 방법(ex. 백트래킹, 구현)과 경우의 수만 다루는 방법(ex. DP) 중에서 고민했는데 제한 사항(n의 크기, 나머지 반환)을 보고 DP로 풀어야할 것 같다는 생각이 들었다.

그런데 테이블 정의를 어떻게 해야할지 막막했다.<br />
2차원 DP로 풀어보려하니 조합이 아닌 순열의 수를 계산하게 되었다. (잘못된 풀이!)

시간이 초과되어 GPT한테 힌트를 얻었는데 그마저도 이해가 안 되어서 삽질을 좀 했다..

다음과 같은 그림을 그려보니 매커니즘이 이해가 되었고 코드를 작성할 수 있었다.<br />
n은 10이고 money는 [2, 5, 3, 1]인 상황이다.

각 화폐 종류에 대해 DP 알고리즘을 수행한다.<br />
이때 테이블은 반복문 밖에 선언해서 화폐 종류별 경우의 수가 누적될 수 있도록 한다.

점화식(아래에 작성)에 따라 테이블의 값을 업데이트해 나간다.

<img width="700" alt="image" src="https://github.com/user-attachments/assets/a1cb8484-1d6e-4d27-a33a-18a53de8cb37" /><br />
완성된 테이블은 그림과 같다.

1. 테이블 정의

   ```
   D[i] = i를 만들 수 있는 경우의 수(단, 마지막 화폐 종류는 현재 화폐 종류여야 함.)
   ```

2. 점화식 세우기

   ```
   D[i] = D[i] + D[i - 현재 화폐 종류]
   ```

3. 초기값 설정

   D\[0]만 1, 그 외에는 0으로 놓고 시작한다(0을 만들 수 있는 방법은 아무것도 사용하지 않는 한 가지 방법밖에 없기 때문이다.).<br />
   i가 현재 화폐보다 작으면 D\[i]를 점화식으로 구할 수 없으므로 i를 현재 화폐부터 시작한다.

연산량은 `100(화폐 종류) * 100,000(n) = 10,000,000`이므로 안전한 풀이라고 생각한다.

### 코드

```js
function solution(n, money) {
  table = Array.from({ length: n + 1 }).fill(0);
  table[0] = 1;
  for (let i = 0; i < money.length; i++) {
    const currentMoney = money[i];
    for (let j = currentMoney; j <= n; j++) {
      table[j] = (table[j] + table[j - currentMoney]) % 1000000007;
    }
  }
  return table[n];
}
```

### 시간 복잡도

**O(NM)**<br />
DP(O(N))를 M(화폐 종류)만큼 반복하기 때문이다.
