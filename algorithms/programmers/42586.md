### 문제 분석 요약

배열을 이용한 구현 문제? 큐?

### 제한 사항

- 작업의 개수(progresses, speeds배열의 길이)는 100개 이하입니다.
- 작업 진도는 100 미만의 자연수입니다.
- 작업 속도는 100 이하의 자연수입니다.
- 배포는 하루에 한 번만 할 수 있으며, 하루의 끝에 이루어진다고 가정합니다. 예를 들어 진도율이 95%인 작업의 개발 속도가 하루에 4%라면 배포는 2일 뒤에 이루어집니다.

### 알고리즘 설계

다음과 같이 알고리즘을 설계했다.

1. 하루마다 다음을 반복
   1. processes의 각 요소를 speeds로 업데이트
   2. 배포 가능한 작업을 세면서 커서를 이동시키고, 배포가 가능하다면 결과 배열 업데이트
2. 결과 배열 반환

최대 99일(작업 진도가 1이고 작업 속도가 1인 경우)을 반복하며, processes 업데이트는 최대 100번(processes 최대 길이), 커서 이동은 일수 상관 없이 총작업 개수만큼 수행되므로 안전하게(?) 풀 수 있다.

### 코드

```py
def solution(progresses, speeds):
    taskCount = len(progresses)

    cursor = 0
    deploymentCounts = []
    while cursor < taskCount:
        for i in range(taskCount):
            if progresses[i] >= 100:
                continue
            progresses[i] += speeds[i]
        deploymentCount = 0
        while cursor < taskCount and progresses[cursor] >= 100:
            deploymentCount += 1
            cursor += 1
        if deploymentCount > 0:
            deploymentCounts.append(deploymentCount)
    return deploymentCounts
```

### 시간 복잡도

**O(N^2)**<br />
작업 개수가 N이라 할 때, N일 동안 N번 업데이트하므로
